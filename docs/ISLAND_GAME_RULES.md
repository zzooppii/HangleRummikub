# 섬 개척 — 기본판과 온라인 정책

## CONFIRMED

2026-09-10 사용자가 카탄 추가 설계(3–4인 기본판, 거래와 2D 보드)를 승인하고 개발을 요청했다. 추가 질문에 **차례 2분, 시간 초과 시 서버가 필요한 선택 후 종료**를 선택했다. 아래는 해당 요청의 구현 기준이다. 기존 한글 게임의 미확정 규칙은 변경하지 않는다.

기본판 기준: [공식 CATAN 기본판 규칙 및 Almanac](https://www.catan.com/sites/default/files/2021-06/catan_base_rules_2020_200707.pdf). 공개 작업명은 앞서 제시한 '섬 개척', 내부 식별자는 ISLAND_SETTLERS. 공식 로고·이미지·규칙서 문장을 복사하지 않고 자체 UI로 표현한다.

- 3–4명. 지형 19개(숲·목초지·농지 각4, 언덕·산 각3, 사막1), 자원 다섯 종류 각각19장. 도로15/마을5/도시4개씩.
- 무작위 지형과 숫자. 6과8이 맞닿지 않게 배치한다. 항구9개(일반3:1 네 개, 자원별2:1 각1).
- 무작위 선 플레이어부터 순방향→역방향으로 마을+도로 두 쌍 배치. 두 번째 마을 주변 자원을 지급한다.
- 두 주사위 생산. 마을1/도시2. 도둑 지형 생산 금지. 자원 부족 시 여러 명이 받을 자원은 지급하지 않고, 한 명만 수령 대상이면 남은 만큼 지급한다.
- 주사위 이후 거래와 건설을 자유롭게 섞는다(공식 Almanac의 combined trade/build).
- 도로: 목재1+벽돌1. 마을: 목재1+벽돌1+양모1+곡물1. 도시: 곡물2+광석3. 발전: 양모1+곡물1+광석1.
- 마을은 인접 교차점과 한 칸 간격, 초기 배치 외에는 자기 도로와 연결. 도로는 자기 거점/도로와 연결하며 상대 거점을 통과하지 못한다.
- 거래에 현재 차례 플레이어가 반드시 참여한다. 자원만 교환하고 무상 양도·동종 자원 맞교환은 금지한다. 제안/응답/확정을 구분하고 최종 확정 시 양쪽 재고를 재검증한다.
- 7: 자원8장 이상인 참가자가 절반(내림)을 버린 뒤 도둑을 다른 지형으로 옮기고 인접 상대 한 명에게서 무작위 자원1장을 가져온다.
- 발전25장: 기사14, 승점5, 도로건설2, 풍년2, 독점2. 산 차례에는 사용할 수 없고 차례당 행동 발전카드1장. 승점은 사용 제한의 예외로 자기 승리 조건에 자동 포함한다. 기사는 주사위 전에도 사용 가능.
- 최장 도로는 중복 간선 없이5개 이상, 최대 기사단은 공개 기사3장 이상. 동률이면 기존 보유자가 유지하고 기존 보유자가 최대값에서 탈락했는데 여러 명이 동률이면 보유자 없음. 각2점.
- 자기 차례에 비공개 승점을 포함해10점 이상이면 즉시 승리.

## DIGITAL_MVP_POLICY

- 한 차례는120초. 초기 배치에서는 한 사람의 마을+도로 한 쌍에120초. 거래·버리기·발전카드 처리로 마감을 연장하지 않는다. 새로고침/재접속도 시간을 연장하지 않는다.
- 마감 시 미완료 초기 배치를 합법적인 위치에 자동 배치한다. 일반 차례는 필요하면 주사위를 굴리고, 대상자 버리기·도둑 이동/훔치기·남은 무료 도로를 서버가 처리한 뒤 종료한다. 새 마감은 서버가 실제로 다음 차례를 시작한 시각부터120초다.
- 자동 선택은 서버에서 제공한 무작위 입력으로 결정하고, 결과를 commit한다. retry는 재추첨하지 않는다.
- 동시에 열린 거래는 하나. 현재 차례 플레이어는 모두에게 제안할 수 있고, 다른 참가자는 현재 플레이어에게 제안할 수 있다. 수정 제안은 상대가 새 조건을 확인하도록 기존 동의를 폐기한다. 제안자만 철회하며 차례 종료 시 자동 취소한다.
- 접속 끊김은 자리/패를 유지하고 타이머가 계속 진행한다. 명시적 나가기는 전체 판 취소 후 같은 방 재시작을 지원한다. 나가기 전에 UI가 이를 설명한다.
- 진행 중에는 상대 자원 총수, 발전 카드 총수, 공개 기사수·공개점수만 제공한다. 사적인 자원 종류, 발전 앞면/ID, 덱 순서, 숨은 승점은 플레이어별 projection으로 보호한다. 종료 시 최종 점수 공개.
- 서버 재시작 복구/DB·영구 저장은 구현하지 않는다. 사용자가 개발하지 않겠다고 명시했으며, 이후 별도로 요청할 때만 검토한다. 기존 process-memory 방식을 유지하고 남은 개발 과제로 취급하지 않는다.
